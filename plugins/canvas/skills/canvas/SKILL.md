# Canvas

A canvas is one self-contained HTML file. It renders in BB beside the chat, in the sidebar, and anywhere else the file is opened: an email attachment, a Slack upload, a Notion HTML block, a static host. It never depends on BB. Every canvas is built on the kit in `references/kit.css` and ends with the credits footer. The directive also accepts Markdown files for plain project docs, but a canvas is HTML.

## When to use one

The trigger is user intent, not response shape. Use a canvas when the output is a standalone thing the user will revisit: a plan, a report, a KPI readout, an audit with categorized findings, a comparison, a large table, a mockup, or a demo. Skip it for drafted messages, code fixes, quick answers, and anything that belongs in another tool.

If the data needed for the canvas is missing, say so in chat. Do not write a canvas with placeholders.

## Workflow

1. Decide the kind: `plan`, `report`, `chart`, `demo`, `notes`, or `mockup`.
2. Write one HTML file. Copy `references/kit.css` into the `<style>` block, keep only the components used, and follow the skeleton and rules in `references/canvas-style.md`. Study `examples/plan.html`, `examples/report.html`, and `examples/mockup.html` before the first canvas of a session.
3. Save it in the right place. Thread storage for generated artifacts: `$BB_THREAD_STORAGE/canvas/<slug>.html`. The workspace only when the file belongs to the project.
4. Visual QA. Render in a headless browser and inspect top, middle, and bottom. Fix defects first.
5. Emit the directive as its own paragraph, outside any code fence, after the file exists on disk.

## Directive

```text
::canvas{source="thread-storage" file="canvas/klaviyo-w38.html" title="Klaviyo flows, week 38" kind="report"}
::canvas{source="thread-storage" file="canvas/standup-28-sep.html" title="Standup notes, 28 Sep" kind="notes" display="inline"}
```

- `file`: path relative to the source. Never absolute. Extensions `.html`, `.htm`, `.md`, `.markdown`.
- `source`: `workspace` (default) or `thread-storage`.
- `title`: required. The human title shown on the card. Same as the page's `<title>`.
- `kind`: one of `plan`, `report`, `chart`, `demo`, `notes`, `mockup`. Drives the icon and label.
- `display`: `card` or `inline`. Default is `card` for HTML and `inline` for Markdown. Use `inline` for a small HTML visual that should be seen without a click.
- `height`: inline only, whole number 120 to 1200 pixels. Default 224.

Do not put the directive in backticks. Emit it complete in one piece.

## Rules

- One document, one `<style>`, Inter from rsms.me, no other external assets, no scripts unless the user asked for interaction.
- Title first. The card shows the title and kind, not the filename.
- Hierarchy over decoration. Sections are open, cards are for named units, no nesting, no dividers.
- Always end with the credits footer: generated by the agent's name, for the user's name, Hello Gafaro, and the date. It is the signature and the trace when the file travels.
- The file must open correctly from disk with no server. Nothing in it may assume BB.
- Label every plot. Never render empty states.
- Keep secrets, credentials, private URLs, and local paths out of the file. A canvas is one file and may be shared later.
- Under 5 MiB. Aim for under 100 KB.

## Pitfalls

- A directive typed before the file exists shows an error. Write, QA, then emit.
- `source` must be exactly `workspace` or `thread-storage`.
- Pasting large HTML into chat instead of a file defeats the purpose. Hand over the canvas, then summarize in two sentences.
