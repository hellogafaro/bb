# Canvas style

Use this reference when writing a canvas: a single-file HTML page that renders anywhere, with no dependency on BB. BB shows it inline in chat and in the sidebar, and the same file can be attached, uploaded, or hosted as is. `kit.css` beside this file is the implementation. Copy the whole kit into the page's `<style>` block, then remove the component blocks the page does not use.

## Brand read

BB's chat, in a page. Flat, quiet, and dense enough to read at a glance. Inter at 14px, near-black warm ink on white, one blue accent, hairline borders, 8px radius. Dark mode follows the system. It should look like a shadcn app screen, not a marketing page and not a dashboard template.

## Hard constraints

- One complete HTML document. All CSS in a single `<style>` in `<head>`.
- Inter from its official distribution, with a system fallback:
  `<link rel="preconnect" href="https://rsms.me/"><link rel="stylesheet" href="https://rsms.me/inter/inter.css">`
- No other external CSS, JS, fonts, or images. No `<script>` unless the user asked for interaction. Data lives in the file.
- Readable with CSS stripped: semantic headings, lists, and tables.
- Under 5 MiB. Aim for under 100 KB.
- Opens correctly from a local file, an email attachment, or any static host. Nothing in the page may assume BB, a server, or a build step.

## Tokens

The kit mirrors BB's theme with shadcn names. Use the variables, never hex literals in markup.

| Token | Use |
| --- | --- |
| `--background`, `--foreground` | Page ground and text |
| `--card`, `--card-foreground` | Card surfaces |
| `--muted`, `--muted-foreground` | Quiet surfaces and secondary text |
| `--secondary` | Neutral badge and progress track |
| `--primary`, `--primary-foreground` | The one accent. Buttons, active states, chart-1 |
| `--success`, `--success-text` | Positive deltas, done states |
| `--warning`, `--warning-text` | Attention |
| `--destructive` | Negative deltas, errors |
| `--border`, `--input` | Hairlines and control borders |
| `--radius` | 8px |
| `--chart-1` to `--chart-5` | Series colors in order: blue, green, orange, purple, red |

## Type scale

| Element | Size / line | Weight |
| --- | --- | --- |
| h1 | 24 / 32 | 600 |
| h2 | 18 / 28 | 600 |
| h3 | 16 / 24 | 600 |
| body | 14 / 21 | 400 |
| `.lead` | 16 / 24, muted | 400 |
| `.text-sm` | 13 / 18 | 400 |
| `.text-xs`, meta, captions | 12 / 16, muted | 400 |
| `.stat-value` | 24 / 32, tabular | 600 |

Never go above 24px. Never put bold sentences in a card header. Long-form text stays under 72 characters per line.

## Spacing

Scale: 4, 8, 12, 16, 24, 32, 48. Related items 8 to 16. Sections 32. Page padding 24, 16 on narrow screens. Max width 800px.

## Document skeleton

```html
<main class="page">
  <header class="page-header">
    <div class="row"><span class="badge badge-outline">{{KIND}}</span><span class="badge badge-info">{{STATUS}}</span></div>
    <h1>{{TITLE}}</h1>
    <p class="lead">{{ONE_OR_TWO_SENTENCES}}</p>
    <div class="page-meta"><span>Owner: {{OWNER}}</span><span>Updated {{DATE}}</span><span>Source: {{SOURCE}}</span></div>
  </header>

  <section class="section">
    <h2>{{FIRST_SECTION_ANSWERS_THE_QUESTION}}</h2>
    <p class="text-muted">{{ONE_LINE_SUBTITLE}}</p>
    ...
  </section>

  <footer class="page-footer"><span>Generated by <strong>{{AGENT}}</strong> for <strong>{{USER}}</strong> · Hello Gafaro</span><span>{{DATE}}</span></footer>
</main>
```

Header and footer are the only places with a border. Sections are open: a heading, a one-line muted subtitle, then content.

The footer is always present. It is the signature and the trace: the agent that wrote the canvas, the person it was written for, the company, and the date. Nothing else goes in it.

## Components

| Component | Classes | Rule |
| --- | --- | --- |
| Page header | `.page-header`, `.page-meta` | Once. Kind badge, status badge, h1, lead, meta line. |
| Page footer | `.page-footer` | Once, last. Generated by agent for user · Hello Gafaro, and the date. |
| Section | `.section` | h2 plus `.text-muted` subtitle. This is the default container. |
| Card | `.card`, `.card-header`, `.card-title`, `.card-description`, `.card-content`, `.card-footer`, `.card-header.with-action`, `.card.compact` | For a named unit: a metric, a chart, an anomaly, a file. Never wrap a whole section in a card. Never nest a card in a card. |
| Stat | `.card.stat`, `.stat-value`, `.stat-delta` with `.up` or `.down` | Three to five per row in `.grid-4`. Label in `.card-description`. |
| Badge | `.badge`, `-secondary`, `-outline`, `-destructive`, `-success`, `-warning`, `-info` | Status and kind. Sentence case, one or two words. |
| Button | `.button`, `-secondary`, `-outline`, `-ghost`, `-sm` | Static links styled as buttons. Rare in a canvas. |
| Alert | `.alert`, `-info`, `-warning`, `-destructive`, `.alert-title`, `.alert-description` | One per section at most. The thing the reader must not miss. |
| Table | `.table-wrap` > `.table`, `th.n` and `td.n` for numbers | Header row muted, numbers right-aligned and tabular. Add a `caption` for source and range when the table is data. |
| Chart | `.card` with `.card-title`, `.card-description`, `.bars`, `.chart-legend`, `.chart-caption` | Title names the metric. Description states unit, method, and range. Legend when more than one series. Caption states source and range. |
| Checklist | `.checklist`, `li.done` | Tasks and next steps. |
| Steps | `.steps`, `li.done`, `li.active`, `.step-head`, `.step-body`, `.step-meta` | Numbered plan with status badge, owner, rollback. Open, not cards. |
| Flow | `.flow`, badges and `.sep` | Short pipelines. Accent on the final or current node only. |
| Tabs, Progress | `.tabs-list`, `.tabs-trigger[data-state=active]`, `.progress`, `.progress-indicator` | Static state display. |
| Key-value | `.kv` (`dl`) | Facts about one thing. |
| Figure | `.figure` | Embedded image or mock with a caption. |
| Grid | `.grid`, `.grid-4` | Cards side by side. Collapses to one column under 420px. |

## Design rules

- Hierarchy: one thing per page stands out. Squint. If everything is the same weight, cut.
- Cards are for named units. Sections are open. Do not wrap sections in cards, do not stack identical cards, do not nest.
- No dividers beyond the header and footer borders. Spacing separates sections.
- No gradients, no shadows, no emoji, no decorative borders, no rainbow. Most elements are neutral; accent is deliberate.
- Label every plot: title with the metric, unit, legend when more than one series, source and range caption. Say when a value is a mean, p95, or normalized.
- Never render an empty state. No placeholder rows, no "No data", no TODO. If the data is missing, say so in chat and do not write the canvas.
- Numbers: tabular figures, thin space thousands separator, unit after the number, deltas with sign and comparison period.
- Copy: short sentences, concrete nouns, honest status. Owner, risk, and rollback on consequential steps. Apply the unslop skill.
- Dark mode: the kit handles it through `prefers-color-scheme`. Do not hardcode colors in markup.
- Narrow screens: the kit collapses grids. Do not hide content to fit.

## Visual QA

Before emitting the directive, render the file in a headless browser and look at the top, middle, and bottom of the page. Check for overlap, overflow, clipped text, and the font actually loading. Fix and re-render. Do not deliver with a known defect.
